2. **Removed the `addgroup`/`adduser` step, `USER app` and `--chown=app:app`.** The minimal image already runs as user 65532, which is what `k8s/deployment.yaml` sets. The app files stay owned by root and readable by everyone, which works with `readOnlyRootFilesystem: true`.
3. **Moved the virtualenv from `/opt/venv` to `/app/venv`.** `RUN` steps in the build stage also run as user 65532, which can't write to `/opt`, so `python -m venv /opt/venv` would likely have been the next failure. I set `WORKDIR /app` first so the user owns that directory. The runtime stage copies the venv to the same path, so the scripts' `#!/app/venv/bin/python` line still points to the right place.
4. **Port 8080 and the start command.** Both images use `/usr/bin/python` as their entrypoint, so the old `CMD ["uvicorn", ...]` would have run as `python uvicorn ...` and failed. It is now `ENTRYPOINT ["/app/venv/bin/uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080"]`, and `EXPOSE` is 8080, which matches the deployment's port and probes.
